① GestureRecognizer.process() — 原始事件 → 高级事件
  MouseDown (x=100,y=50)
  │
  ├─► 记录 PointerState{downPos=(100,50), downTime=T0, panStarted=false}
  │   返回: [] (尚无高级事件)
  │
  │  ... 若干帧后 ...
  │
  MouseUp (x=103,y=53)   // 距离=5px < 阈值, 耗时=200ms < 超时
  │
  ├─► 判定: 距离<10px 且 时间<500ms → Tap ✓
  │   返回: [UIEvent{type=Tap, position=(103,53), timestamp=T1}]
  │
  另一种情况:
  MouseUp (x=150,y=200)  // 距离=164px > 阈值
  (前提: MouseMove 过程中已触发 PanBegin)
  │
  ├─► 返回: [UIEvent{type=PanEnd, position=(150,200)}]
  长按情况:
  MouseDown → 600ms 后 → 中间无 Move / 仍在原地
  │
  ├─► (在 MouseUp 时判定: elapsed>600ms 且 dist<10px)
  │   返回: [UIEvent{type=LongPress, position=...}]
原始事件	产生的高级事件	条件
MouseDown	无（仅记录状态）	—
MouseDown…MouseUp（快速近距离）	Tap	距离 < 10px，耗时 < 500ms
MouseDown…保持原地…MouseUp	LongPress	距离 < 10px，耗时 > 600ms
MouseDown…MouseMove（超过阈值）	PanBegin + 后续 PanMove	移动 > 5px
PanMove…MouseUp	PanEnd	—
MouseMove（无按下）	HoverMove	始终生成

② EventDispatcher.dispatch() — 命中测试 + 三阶段传播
  dispatch(root, UIEvent{type=Tap, position=(150, 200)})
  Step 1: hitTest
  ┌──────────────────────────────────┐
  │  root.hitTest(Point{150,200})   │
  │                                  │
  │  root.frame=(0,0,800,600) ✓     │
  │  ├─ child[0] frame=(20,20,200,100) │
  │  │   └─ Point{150,200} → 不在frame内 → skip
  │  ├─ child[1] frame=(20,120,760,480) │
  │  │   └─ contains ✓                 │
  │  │       ├─ child[1].children[0] → 不在frame → skip
  │  │       └─ child[1].children[1] → contains ✓
  │  │           └─ 无子节点 → 返回 child[1].children[1]
  │  │                                     │
  │  └─   命中目标: child[1].children[1]  ◄┘
  └──────────────────────────────────┘
  Step 2: collectPath (构建路径, 用于后续三阶段)
  ┌───────────────────────────────┐
  │ path = [                      │
  │   root,                       │  ← 阶段1捕获: 正向遍历 (除target)
  │   child[1],                   │
  │   child[1].children[1]        │  ← target
  │ ]                             │  ← 阶段3冒泡: 反向遍历 (除target)
  └───────────────────────────────┘
  Step 3: 三阶段传播
  ┌─────────────────────────────────────────────────┐
  │                                                 │
  │  阶段1: 捕获 (capture)                          │
  │    path[0] = root.onEvent(Tap, ...)             │
  │       → 有 onClick 吗? 没有 → 继续              │
  │    path[1] = child[1].onEvent(Tap, ...)         │
  │       → 有 onClick 吗? 没有 → 继续              │
  │                                                 │
  │  阶段2: 目标 (target)                           │
  │    path[2] = child[1].children[1].onEvent(Tap)  │
  │       → onClick = JS function ◄── 匹配! 调用    │
  │       → 返回 true (或 false 取决于 JS 函数行为) │
  │                                                 │
  │  阶段3: 冒泡 (bubble)  — 仅当目标未消费时执行   │
  │    path[1] = child[1].onEvent(...)              │
  │    path[0] = root.onEvent(...)                  │
  │                                                 │
  └─────────────────────────────────────────────────┘

③ View.onEvent() — C++ 内部调用 JS 回调
  onEvent(eventCode=0, localX=30, localY=40, ctx)
  │
  ├─► switch(eventCode): case 0 → handler = onClick (JSValue)
  │
  ├─► 校验: handler != JS_NULL && JS_IsFunction(ctx, handler)
  │
  ├─► 构造 JS 事件对象: { x: 30, y: 40 }
  │
  ├─► JS_Call(ctx, handler, JS_UNDEFINED, 1, &eventObj)
  │         │
  │         ▼
  │    ┌──────────────────────────────────────────┐
  │    │  js 侧代码:                               │
  │    │                                           │
  │    │  Button({                                 │
  │    │    text: "Click me",                      │
  │    │    onClick: function(event) {             │
  │    │      console.log(event.x, event.y);       │
  │    │      appState.count++;   ◄── 触发 State   │
  │    │    }                                      │
  │    │  })                                       │
  │    │                                           │
  │    │  State.set_property("count", newValue)    │
  │    │    → render_callback()                    │
  │    │      → jsContext.requestRender()          │
  │    │        → needRender = true                │
  │    └──────────────────────────────────────────┘
  │
  ├─► JS_FreeValue 清理临时对象
  │
  └─► 返回 true (事件已消费)

④ 状态变更触发重渲染
  jsContext.needRender = true
  │
  │  (主线程下一帧开始时检查)
  ├─► jsContext.isRenderNeeded() → true
  │
  ├─► tree = ElementParser::parse(ctx, jsContext.getRootView())
  │     │
  │     ├─► 遍历 JS 对象树 {type:"View", props:{...}, children:[...]}
  │     ├─► 查注册表: "View" → make_unique<View>(props)
  │     ├─► 解析 props → ViewProps
  │     ├─► 提取 onClick/onLongPress... → JS_DupValue 绑定到 View
  │     └─► 递归解析 children
  │
  ├─► tree->measure(Constraints::loose(winSize))
  ├─► tree->layout(Rect(0,0,w,h))
  │
  ├─► jsContext.clearRenderFlag()
  │
  └─► tree->draw(canvas) → 帧绘制

一个待注意的设计点
当前 EventDispatcher::dispatch() 中 fireOnView 返回 true（事件已消费），但 View::onEvent() 的实现中如果 JS 函数执行成功始终返回 true。这意味着：
- 目标视图的 onClick 被触发后，冒泡阶段不会执行（被 true 阻止）
- 如果希望事件继续冒泡，需要 JS 回调显式返回 false
这与 React 的 e.stopPropagation() 行为相似，但默认即阻止冒泡。如果你希望默认冒泡，将 View::onEvent() 返回值改为始终返回 false 即可。
