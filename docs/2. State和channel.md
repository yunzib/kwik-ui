# 2. State 响应式状态

State 是框架内置的响应式状态容器。写入属性自动触发 UI 重建，配合函数式导出实现声明式动态 UI。

## 2.1 创建

```js
import { State, ref } from 'kwikui';
const form = new State({ name: "张三", agree: false, city: "北京" });
//      ^^^ 必须带 new
```
## 2.2 特点
- **增量更新优先**：`form.key = val` 优先走增量路径，直接更新绑定的组件属性，
  无需重建 View 树。无绑定时回退整树重建。
- **全量重建保留**：`State.update()` 以及未注册绑定的属性写入，仍走 `rebuildTree`。
- 仅函数式导出 `export default () => View(...)` 响应 State 变化；
  对象式导出 `export default View(...)` 不受 State 影响。
- `form.key = ""`（空串）也会触发增量/重建检查。
- state.update({a,b}) 批量更新时逐键尝试增量，全部命中跳过 rebuildTree；
任一键未绑定则回退全量重建。与 state.count++（单键 always 增量）互补。

## 2.3 用法
```
export default () => View({}, [
    Text({ text: form.name }),                        // 直接引用
    Checkbox({ checked: ref(form, "agree") }),        // 双向绑定
]);
```
### 双向绑定 ref(state, key)

ref 绑定支持**全部 26 种组件类型**（View、Text、Button、Flex、Grid、Stack、List、
Image、Input、Checkbox、TextArea、Dropdown、RadioButton、RadioGroup、Slider、
ProgressBar、Switch、Line、Spinner、Table、Tabs、Dialog、Tip、TextView、G2D）。

```js
View({ background: ref(state, "bgColor"), opacity: ref(state, "alpha") }),
Text({ text: ref(state, "title"), color: ref(state, "titleColor") }),
```
ref 标记在 makeElement 内部由 resolveAllRefProps 统一识别并展开：
- 将 ref(state, "key") 替换为 state 当前值
- 注入 __bind_{propName}State/Key 隐藏属性，供 C++ applyBindings 消费
增量更新路径：State 属性变更 → BindingRegistry 查询 → setPropertyTyped + markDirty（无树重建）。
全量重建回退：State.update({...}) 中部分 key 无绑定 / 结构性 JS 变化。


### 增量更新与组件内属性同步

`state.key = val` 的增量路径最终调用 `view->setPropertyTyped(propName, typedValue)`。
View 基类通过 `propIdFromName` 分派 ViewProps 通用字段（width/height/background 等）。
如果组件新增了 ViewProps 之外的特有属性（如 Text 的 text_），**必须覆写 `setPropertyTyped`**
处理该属性，否则增量更新返回 false 但不报错，文字不会变。

**覆写模板（以 Text 为例）**：

// cppm 声明
bool setPropertyTyped(const char *name, const TypedProp &value) override;
// cpp 实现
bool Text::setPropertyTyped(const char *name, const TypedProp &value) {
    if (std::strcmp(name, "text") == 0) {
        if (auto s = std::get_if<std::string>(&value)) {
            text_.text = s;
            layoutResult_.reset();   // 文字变更需废止排版缓存
            markDirty();
            return true;
        }
        return false;
    }
    return View::setPropertyTyped(name, value);
}

### 最佳实践

- 放入 State 的字段只限于需要 `ref()` 绑定到 UI 的键。不需绑定的计数值、中间状态
  等用普通 JS 变量（`let count = 0`），避免无谓触发 rebuildTree。
- `state.update({...})` 批量更新时逐键尝试增量。建议确保所有 key 都有 ref 绑定，
  以走完整的增量路径（跳过 rebuildTree）。
- `resolveAllRefProps` 依赖 `JS_GetOwnPropertyNames(ctx, &tab, &len, props,
  JS_GPN_STRING_MASK | JS_GPN_ENUM_ONLY)` 中的 **STRING_MASK 必须与 ENUM_ONLY 组合**，
  否则 QuickJS 返回空属性列表导致 ref 标记不被解析。

### 与 PropBus 协作
- setProp 在双向绑定的组件上会间接更新 State：
  setProp("userName", "value", "新值");
  → binding → form.name = "新值" → 增量/重建
- getProp / setProp 读写本身不触发重建，适合高频操作。

## 2.4 注意事项
- 1. 函数内不要缓存 State 值：const name = form.name 在 rebuild 时不会更新
- 2. Input/TextArea 不在每键敲击时同步 State（避免光标丢失），仅在 blur 和 setProp 时写入
- 3. ref() 仅在组件创建时生效，不支持运行时修改绑定
- 4. 双向绑定不阻止旧 onChange 回调
- 5. 对象式导出 export default View(...) 不受 State 影响
- 6. ref() 绑定覆盖全部组件类型的任意属性。state.key = val 查 BindingRegistry：
命中→增量；未命中→全量重建。state.update({...}) 同逻辑批量执行。

# 3. PropBus 属性总线
通过 id 和 getProp/setProp 直接读写组件属性，无需 State 参与，不触发 rebuildTree。
适用于非受控模式 (如 TextArea) 或高频读写场景。
- 示例：
```
import { getProp, setProp } from 'kwikui';

// 读取
const value = getProp("textarea1", "value");

// 写入
setProp("textarea1", "value", "新的内容");
setProp("input1", "value", "");
setProp("view1", "background", "#F44336");
```


# 4. Channel 双向通信

Channel 是 C++ 与 JS 之间的双向通信框架，支持单向通知和请求-响应两种模式，
跨线程安全。

## 4.1 通信模式

| 方向 | 模式 | JS API | C++ API |
|------|------|--------|---------|
| JS → C++ | 通知（单向） | `channel.send(topic, data)` | `Channel::on(topic, handler)` |
| C++ → JS | 通知（单向） | `channel.on(topic, handler)` | `Channel::send(topic, data)` |
| JS → C++ | 调用（双向） | `channel.call(topic, data)` | `Channel::handle(topic, handler)` |

## 4.2 JS → C++ 通知

**JS 发送（发后即忘，无返回值）：**
```js
channel.send('button_click', { id: Date.now() });
C++ 接收：
Channel::on("button_click", [](const Channel::Data& d) {
    Log::info("收到通知: {}", d.asString());
});
JS 侧的 send() 是同步调用，数据入队后由主线程下一帧 flush() 时分发给 C++ on handler。
```
## 4.3 C++ → JS 通知
```
C++ 发送（线程安全，可跨线程调用）：
Channel::send("sensor:temp", "temp:25.3,humidity:68.5,count:3,status:normal");
JS 接收：
channel.on('sensor:temp', function(d) {
    state.temp = parseFloat(d.split(',')[0].split(':')[1]);
});
C++ 端在任意线程调用 Channel::send() 入队，主线程 Channel::flush() 时帧合并后统一派发 JS on handler。
```
## 4.4 双向调用

### JS 发起调用（返回 Promise）：
```
const theme = await channel.call('get_config', { key: 'theme' });
// theme === "dark_theme"
C++ 端支持三种 handler 模式，不暴露 JS 类型，统一使用 Channel::Data：
同步 handler
同步执行，直接返回 Data：
Channel::handle("get_config", [](const Channel::Data& d) -> Channel::Data {
    Log::info("[同步] JS → C++ call 'get_config': {}", d.asString());
    return Channel::Data("dark_theme");
});
```
### 异步线程 handler（Responder 回调）
通过 Responder 回调返回结果，适用于耗时操作：
```
Channel::handle("start_download", [](const Channel::Data& d, auto respond) {
    Log::info("[异步线程] JS → C++ call 'start_download': {}", d.asString());
    std::thread([d, respond] {
        std::this_thread::sleep_for(std::chrono::milliseconds(500));
        Channel::getMainThreadQueue().post(
            [respond, result = std::string(d.asString())] {
                respond(Channel::Data("Downloaded: " + result));
            });
    }).detach();
});
Responder 回调必须回到主线程调用（通过 getMainThreadQueue().post()），
Channel::handleCall 内部通过 postToMain 将结果投递回主线程 resolveCall。
```
### 协程 handler（CoroTask）
使用 C++20 协程，自动在 final_suspend 中 respond 并销毁协程帧：
```
Channel::handle("process_file", [](Channel::Data d) -> Channel::CoroTask {
    Log::info("[协程] JS → C++ call 'process_file': {}", d.asString());
    co_await Channel::thread_pool();
    std::this_thread::sleep_for(std::chrono::milliseconds(100));
    std::string content = "Processed: " + std::string(d.asString());
    co_await Channel::main_thread();
    co_return Channel::Data(content);
});
```
## 4.5 CoroTask 说明
CoroTask 是框架内置的 fire-and-forget 协程类型：
- initial_suspend → suspend_never：创建后立即执行到第一个 co_await
- final_suspend → 调用 respond_() 将结果返回 JS，然后 h.destroy() 自销毁
- 返回值通过 co_return Channel::Data(value) 传递
- 注意事项：
    - 1. 参数 const Data& d 在首次 co_await 后会成为悬挂引用，因为原始对象在 jsCall() 返回时已销毁。
必须在首次挂起前复制：Channel::Data dataCopy = d;
    - 2. 推荐 handler 签名改为传值 (Data d)，确保协程帧拥有独立副本
    - 3. co_await thread_pool() 切换到工作线程，co_await main_thread() 切回主线程
## 4.6 数据类型
Channel::Data 是 C++ handler 与 JS 之间的数据桥梁，不暴露 JS 类型：
```
struct Data {
    std::variant<std::monostate, bool, int64_t, double, std::string> _data;
    Data();
    Data(bool);
    Data(int64_t);
    Data(double);
    Data(const std::string&);
    Data(const char*);

    bool isNull() const;
    bool isBool() const;
    bool isInt() const;
    bool isNumber() const;
    bool isString() const;

    bool asBool() const;
    int64_t asInt() const;
    double asNumber() const;
    std::string_view asString() const;
};
JS 对象/数组在跨线程传递时自动 JSON 序列化为字符串，
JS handler 收到后需自行 JSON.parse()。
```
## 4.7 JS API 速查
```
import { channel } from 'kwikui';

// 发送通知（JS → C++，无返回值）
channel.send(topic, data);          // data 可以是对象/数组/基本类型

// 接收通知（C++ → JS）
channel.on(topic, function(data) {
    // data 是字符串（C++ 端 String 类型）或基本类型
});

// 调用 C++ handler（返回 Promise）
const result = await channel.call(topic, data);
```
## 4.8 C++ API 速查

```
// 接收 JS 通知
Channel::on("topic", [](const Data& d) { });

// 发送通知到 JS（线程安全）
Channel::send("topic", data);       // data: bool / int64_t / double / string

// 注册同步 handler
Channel::handle("topic", [](const Data& d) -> Data { ... });

// 注册异步 handler（Responder 回调，必须在主线程调用 respond）
Channel::handle("topic", [](const Data& d, auto respond) { ... });

// 注册协程 handler（传值避免悬挂）
Channel::handle("topic", [](Data d) -> CoroTask { ... });

// 协程调度
co_await Channel::thread_pool();     // 切到工作线程
co_await Channel::main_thread();     // 切回主线程

// 获取主线程任务队列（用于 respond 投递）
Channel::getMainThreadQueue();

```
## 4.9 线程安全
| 操作 | 线程安全 | 说明 |
|------|----------|------|
| `Channel::send()` | ✅ 任意线程 | 数据入队，主线程 `flush` 时派发 |
| `Channel::on()` / `Channel::handle()` | ❌ 主线程 | 注册 C++ handler |
| `Channel::postToMain()` | ✅ 任意线程 | 投递任务到主线程队列 |
| `Channel::getMainThreadQueue()` | ✅ 任意线程 | 获取主线程 `TaskQueue` 引用 |
| JS `channel.send()` / `channel.on()` / `channel.call()` | ❌ 主线程 | JS 引擎单线程 |
| 协程 `thread_pool()` / `main_thread()` | ✅ | 基于 `Scheduler` 线程池 |
| JS handler 执行 | ❌ 主线程 | `Channel::flush()` 中 `JS_Call` |
