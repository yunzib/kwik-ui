# 0. 快速上手

# 一、框架介绍

**KwiK UI 是声明式跨平台 UI 框架：界面用 JS 写成组件树，C++ 内核解析建树、
布局并录制绘制命令，Vulkan GPU 渲染**。C++ 做底层与性能，JS 做界面逻辑，
面向嵌入式 Linux 与跨平台应用。

## 它怎么运作

```
 你写的 JS（组件树描述）
        │  组件工厂 makeElement / 属性解析
        ▼
 C++ View 树（真实控件树）
        │  布局 + 绘制命令录制
        ▼
 Vulkan 渲染线程回放 → GPU 上屏
```

- 界面文件就是普通 JS，`import` 框架模块 `kwikui`，用工厂函数搭树：
  `View({...})`、`Text({...})`，容器第二个参数是 children 数组
- 状态变化自动刷新界面：`const st = new State({ n: 0 })`，
  `st.n++` 后用到 `st.n` 的界面自动更新；需要把某个属性交给 State 控制
  时写 `ref(st, "key")`
- JS 与 C++ 双向通信走 Channel 模块；定时器/周期回调引擎内置
  （用到了再查 [4. Channel](4.%20Channel.md) /
  [8. 运行时与生命周期](8.%20运行时与生命周期.md)）
- 一个窗口对应一棵 UI 树（独立 JS 上下文 / 渲染线程），一个进程可开多窗

# 二、搭一个基础项目

## ① 前置环境

| 依赖 | 最低版本 |
|---|---|
| CMake | 4.3.2 |
| Ninja | 1.13 |
| 编译器 | llvm-mingw-20260421-ucrt-x86_64（或 Clang ≥ 18，需支持 C++ Modules） |
| Vulkan SDK | 1.4（构建期装卸的 SDK 包版本）。注意 SDK 版本与 apiVersion 是**两个东西**：框架的 Vulkan 实例按 `VK_API_VERSION_1_1` 创建（`src/render/vulkan/vulkan_context.cpp:263`），即运行最低要求是驱动支持 1.1，与 SDK 包版本无直接关联。SDK 可选，找不到则自动创建 stub target |

## ② 编译框架源码

```bash
# 在框架仓库根目录执行（用你本地的编译器路径替换下例）
cmake -DCMAKE_BUILD_TYPE:STRING=Debug \
      -DCMAKE_EXPORT_COMPILE_COMMANDS:BOOL=TRUE \
      -DCMAKE_C_COMPILER:FILEPATH=C:\software\llvm-mingw\bin\clang.exe \
      -DCMAKE_CXX_COMPILER:FILEPATH=C:\software\llvm-mingw\bin\clang++.exe \
      --no-warn-unused-cli \
      -S . -B build -G Ninja
cmake --build build --config Debug --target all
```

编译产物在 `build/test/example.exe`（多示例演示程序）。想先自检编译质量，
可跑纯逻辑单测：`ctest --test-dir build`。

## ③ 跑通内置示例（验证环境 OK）

```bash
cd build/test
./example.exe glass        # 打开一个液态玻璃示例窗口
./example.exe button       # 换一个：按钮示例
```

`example.exe` 后面跟示例名，内置示例都注册在 `test/example.cpp` 的
`resolveDemo` 里。一次全部自检用冒烟测试（默认集 38 示例）：

```bash
python ../../test/tools/smoke.py            # 38 示例全自动退出 + 错误扫描
python ../../test/tools/smoke.py glass      # 只跑指定示例
```

不建工程、快速试一段 JS：`resolveDemo` 没注册的名字会**原样当作 jsPath**
（`test/example.cpp:135`），传任意 .js 相对路径就能跑（路径相对 build/test）：

```bash
./example.exe ../../test/ui/mypage.js
```

## ④ 建立自己的项目

仓库里有一份**外部宿主参考工程**：`examples/external/`（CMakeLists.txt、
main.cpp、build.bat 三个文件 + 可复制的字体目录）。你的项目就是它的
"最小化翻版"（Channel 演示段不需要，JS 换成自己的），目录：

```
my-app/
├─ CMakeLists.txt        # 框架接入的构建脚本（见下）
├─ main.cpp              # C++ 宿主入口（见下）
├─ app.js                # 你的 UI（见下）
├─ build.bat             # 一键构建脚本（见下）
└─ fonts/                # 字体目录：从主仓库 resources/fonts/ 复制一份
```

**CMakeLists.txt**（与 `examples/external/CMakeLists.txt` 同源，整段可直接
用，改可执行文件名与 `ENTRY` 路径即可）：

```cmake
cmake_minimum_required(VERSION 4.3.2)
set(CMAKE_C_STANDARD 23)
set(CMAKE_C_STANDARD_REQUIRED ON)
set(CMAKE_C_EXTENSIONS OFF)
set(CMAKE_CXX_STANDARD 26)
set(CMAKE_CXX_STANDARD_REQUIRED ON)
set(CMAKE_CXX_EXTENSIONS OFF)
# 启用 C++ 模块支持
set(CMAKE_CXX_MODULE_STD ON)
set(CMAKE_CXX_SCAN_FOR_MODULES ON)
# 生成 compile_command.json
set(CMAKE_EXPORT_COMPILE_COMMANDS ON)
# 启用 C++23 标准库模块导入
set(CMAKE_EXPERIMENTAL_CXX_IMPORT_STD  "451f2fe2-a8a2-47c3-bc32-94786d8fc91b")
set(CMAKE_EXPERIMENTAL_MAPPED_PACKAGE_INFO "ababa1b5-7099-495f-a9cd-e22d38f274f2")
set(CMAKE_EXPERIMENTAL_GENERATE_SBOM "ca494ed3-b261-4205-a01f-603c95e4cae0")

project(kwik-demo LANGUAGES C CXX)

# ── 默认 Debug 构建 ──
# 命令行覆盖：cmake -B build -DCMAKE_BUILD_TYPE=Release
if(NOT CMAKE_BUILD_TYPE)
    set(CMAKE_BUILD_TYPE Debug CACHE STRING
        "Debug=filesystem+hotreload, Release=embedded bytecode" FORCE)
endif()

find_package(kwik-ui REQUIRED)

add_executable(kwik-demo main.cpp)

# kwik_js 连接 JS 入口：
#   Debug   → jsPath 文件系统加载 + 热重载
#   Release → 编译为字节码嵌入 exe（ENTRY 只在配置阶段用）
kwik_js(kwik-demo ENTRY app.js)
target_link_libraries(kwik-demo PRIVATE kwik-ui::kwik)

# 装载框架 C++ 模块（main.cpp 里的 import kwik.* 靠这段编译）
target_sources(kwik-demo PRIVATE
  FILE_SET cxx_modules TYPE CXX_MODULES
  BASE_DIRS "${kwik-ui_MODULES_DIR}"
  FILES ${kwik-ui_MODULE_FILES}
)

# 用法：
# build.bat            # Debug（默认）→ IS_DEV_BUILD=1 → 文件系统 + 热重载
# build.bat Release    # Release → IS_DEV_BUILD=0 → 嵌入式字节码，发布时使用
```

**main.cpp**（最小宿主：建窗口 → 挂树 → 跑起来）：

```c++
#if defined(_WIN32)
#include <Windows.h>
#endif
#include <memory>

import kwik.platform.window;
import kwik.platform.win32_window;
import kwik.app;
import kwik.core.log;

int main() {
#if defined(_WIN32)
    SetConsoleOutputCP(CP_UTF8);
    SetConsoleCP(CP_UTF8);
#endif
    // ① 建窗口
    auto window = std::make_unique<PlatformWindowWin32>();
    if (!window || !window->Create("My App", 1280, 800)) return -1;
    window->Show();

    // ② 挂树：IS_DEV_BUILD 由 kwik 包按构建类型注入（Debug=1 / Release=0，
    //    见上面 CMakeLists 的用法注释），两态二选一
    Application app;
#if IS_DEV_BUILD                        // Debug：文件系统 + 热重载
    app.createRuntime(*window, {
        .jsPath          = "app.js",    // 你的 UI 入口
        .enableHotReload = true,        // 改 JS 存盘即重载
        .fontDirs        = {"fonts"}     // 字体目录
    });
#else                                   // Release：字节码已嵌入 exe
    app.createRuntime(*window, {
        .enableHotReload = false,
        .fontDirs        = {"fonts"}
    });
#endif

    // ③ 跑起来（主循环在 app.run() 里）
    return app.run();
}
```

**app.js**（真正能跑的最小页面）：

```js
import { View, Text, Button, State, Root } from 'kwikui';

const st = new State({ n: 0 });

export default () => Root(
    View({ width: 400, height: 240, background: '#FFFFFF', padding: 20 }, [
        Text({ text: '计数: ' + st.n, fontSize: 20 }),
        Button({ text: '+1', width: 80, height: 36,
                 onClick: () => { st.n++; } }),
    ])
);
```

看到了什么：一个白底窗口，`计数: 0` 和一个 `+1` 按钮——点一下计数加一，
界面自动刷新。这就是整套框架的最小闭环：**JS 描述树 → C++ 树 → 自动响应**。

**build.bat**（一键构建；与 `examples/external/build.bat` 同源）：

```bat
@echo off
set CONFIG=%1
if "%CONFIG%"=="" set CONFIG=Debug
set SDK_DIR=%~dp0..\..\build\install
cmake -B build -G Ninja -DCMAKE_PREFIX_PATH=%SDK_DIR% -DCMAKE_BUILD_TYPE=%CONFIG%
cmake --build build
```

注意 `SDK_DIR` 那行：原工程里 `%~dp0..\..` 指回仓库根目录找
`build/install`。你的 `my-app` 若放在仓库外，把它改成**你实际安装 SDK 的
绝对路径**（或相对路径）即可；否则跑不起来。

**构建与运行自己的项目**（在 my-app 目录下；`jsPath` 和 `fontDirs` 都是
相对**运行时工作目录**解析的，所以从 my-app 根目录运行，路径才对得上
`app.js` 与 `fonts/`）：

```bash
# 前提：框架 SDK 已装出（一次性；在框架仓库根目录执行）
cmake --install build --prefix build/install

# 方式一：脚本
build.bat            # Debug（默认）：文件系统 + 热重载
build.bat Release    # Release：UI 编译为嵌入式字节码，发布时使用

# 方式二：手动
cmake -B build -G Ninja -DCMAKE_PREFIX_PATH=<框架根>/build/install
cmake --build build
./build/kwik-demo.exe
```

## ⑤ 开发与发布

**开发（Debug）**：热重载开着（`enableHotReload = true`），直接改
`app.js` 存盘——窗口内容自动更新，不用重新编译。调试手段：
`console.log()` 输出到进程控制台；C++ 侧 `Log::info(...)`
（`import kwik.core.log`）。

**发布（Release）**：`build.bat Release`（或手动
`-DCMAKE_BUILD_TYPE=Release`）。UI 文件在构建期由 kwik_js 按 `ENTRY`
编译为字节码并嵌入 exe——JS 零外部文件依赖、无运行时解析，性能与
原生 C++ 持平。注意发布物是**单个 exe + `fonts/` 字体目录**：
字体是运行期从 `fontDirs` 加载的资源（`src/app/kwik_runtime.cpp:175`
交给 FontManager 扫描），要随包一起携带。

**进阶可选**：
- JS↔C++ 双向通信（Channel 三种 handler 形态）：
  [4. Channel](4.%20Channel.md)，宿主侧完整示例见
  `examples/external/main.cpp` 的 ChannelTest 段落
- 定时器 / rAF / 生命周期挂载点：[8. 运行时与生命周期](8.%20运行时与生命周期.md)
- 扩展组件（Video / G3D）注册：主入口必须在 Application 构造**前**调
  `registerVideoElement()`（对照 `test/example.cpp:149-150`）
- 多窗口：每窗一次 `app.createRuntime(win, {...})`，窗口对象须活过 app
  （对照 `test/example.cpp:155-167` dual 模式）
