# PropBus 属性总线

通过 id 和 getProp/setProp 直接读写组件属性，无需 State 参与，不触发 rebuildTree。
适用于非受控模式 (如 TextArea) 或高频读写场景。

## 示例

```
import { getProp, setProp } from 'kwikui';

// 读取
const value = getProp("textarea1", "value");

// 写入
setProp("textarea1", "value", "新的内容");
setProp("input1", "value", "");
setProp("view1", "background", "#F44336");
```

两通道互补：State 写入按 ref 绑定触发增量更新或 rebuildTree 重建，PropBus 的 getProp/setProp 命令式读写不触发 rebuildTree；响应式绑定见 [State](2.%20State.md)。

## 写入的生命周期

`setProp` 是**即时写入**，不是**持续声明**——它改的是组件此刻的属性值，而这个值只活到下一次 rebuildTree 之前。

```
View({ id: 'preview', background: '#808080' })

setProp('preview', 'background', '#FF0000')   // ① 立刻变红
state.tick = 1                                 // ② 任意 State 写入
// ③ rebuildTree → reconcile 按 JS 字面量重放 → background 回到 #808080
```

原因：`setProp` 只改 `props` 并 `markDirty()`（触发重绘，不建树）；而 State 写入会触发 rebuildTree，`ElementParser::reconcileNode` 复用节点时按 JS 侧道具**整体重放** ViewProps（`src/bridge/element_parser.cpp:979`），命令式写入的字段被原样盖回。

典型踩坑：在滑杆的 `onChange` 里 `setProp` 改预览色。State 写入与 setProp 发生在同一帧，rebuild 紧随其后，写入连一帧都活不到——表现为「拖动预览色不变」，而旁边的数字（JS 字面量重放）正常跟着变。

### 是否可持续生效

| 写法 | 结果 | 说明 |
|---|---|---|
| `ref` 绑定 + Bool/Int/Float/String | 持久 | `echoBoundState` 把写入值回写 State，下一轮重放的就是新值 |
| `ref` 绑定 + Color/枚举等 | 重建即回退 | 命令式回声只覆盖标量类型，Color 无回写通道 |
| 未绑定 + 之后没有 rebuild | 暂时生效 | 任何 State 写入、热重载都会让它复位 |
| 未绑定 + 同帧 rebuild | 无效 | 写入当场被 JS 字面量覆盖 |

后两类的「能用」属于碰巧：界面上别处一次 State 写入，就会让这些靠 setProp 维持的状态整片复位。

### 需要持续生效时

交给 State 派生，让重建重放正确的值——重建从「覆盖者」变成「刷新手段」：

```
const hex = (n) => Math.round(n).toString(16).padStart(2, '0');
View({ background: `#${hex(s.red)}${hex(s.green)}${hex(s.blue)}` })
```

原则：**出现在 JS 渲染结果里的属性由 JS 决定**。`setProp` 适合改那些 JS 不再声明的属性——非受控组件的即时回写、临时提示、不依赖 State 的动画旁路。
