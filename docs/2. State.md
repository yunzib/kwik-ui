# State 响应式状态

State 是框架内置的响应式状态容器。写入属性自动触发 UI 重建，配合函数式导出实现声明式动态 UI。

## 2.1 创建

```js
import { State, ref } from 'kwikui';
const form = new State({ name: "张三", agree: false, city: "北京" });
//      ^^^ 必须带 new
```
## 2.2 特点
- **增量更新优先**：`form.key = val` 优先走增量路径，直接更新绑定的组件属性，
  无需重建 View 树。无绑定时回退整树重建。
- **全量重建保留**：`State.update()` 以及未注册绑定的属性写入，仍走 `rebuildTree`。
- 仅函数式导出 `export default () => View(...)` 响应 State 变化；
  对象式导出 `export default View(...)` 不受 State 影响。
- `form.key = ""`（空串）也会触发增量/重建检查。
- state.update({a,b}) 批量更新时逐键尝试增量，全部命中跳过 rebuildTree；
任一键未绑定则回退全量重建。与 state.count++（单键 always 增量）互补。

## 2.3 用法
```
export default () => View({}, [
    Text({ text: form.name }),                        // 直接引用
    Checkbox({ checked: ref(form, "agree") }),        // 双向绑定
]);
```
### 双向绑定 ref(state, key)

ref 绑定支持**全部 26 种组件类型**（View、Text、Button、Flex、Grid、Stack、List、
Image、Input、Checkbox、TextArea、Dropdown、RadioButton、RadioGroup、Slider、
ProgressBar、Switch、Line、Spinner、Table、Tabs、TextView、G2D、ThemeProvider、LayerView）。

```js
View({ background: ref(state, "bgColor"), opacity: ref(state, "alpha") }),
Text({ text: ref(state, "title"), color: ref(state, "titleColor") }),
```
ref 标记在 makeElement 内部由 resolveAllRefProps 统一识别并展开：
- 将 ref(state, "key") 替换为 state 当前值
- 注入 __bind_{propName}State/Key 隐藏属性，供 C++ applyBindings 消费
增量更新路径：State 属性变更 → BindingRegistry 查询 → 命中且可补间（含 transitionDuration）
→ 隐式 transition 自动补间（动画逐帧写入 + markDirty）；否则 setPropertyTyped + markDirty（无树重建）。
全量重建回退：State.update({...}) 中部分 key 无绑定 / 结构性 JS 变化。


### 增量更新与组件内属性同步

`state.key = val` 的增量路径最终调用 `view->setPropertyTyped(propName, typedValue)`。
View 基类通过 `propIdFromName` 分派 ViewProps 通用字段（width/height/background 等）。
如果组件新增了 ViewProps 之外的特有属性（如 Text 的 text_），**必须覆写 `setPropertyTyped`**
处理该属性，否则增量更新返回 false 但不报错，文字不会变。

**覆写模板（以 Text 为例）**：

// cppm 声明
bool setPropertyTyped(const char *name, const TypedProp &value) override;
// cpp 实现
bool Text::setPropertyTyped(const char *name, const TypedProp &value) {
    if (std::strcmp(name, "text") == 0) {
        if (auto s = std::get_if<std::string>(&value)) {
            text_.text = s;
            layoutResult_.reset();   // 文字变更需废止排版缓存
            markDirty();
            return true;
        }
        return false;
    }
    return View::setPropertyTyped(name, value);
}

**纯赋值约束（重要）**：`setPropertyTyped` 是唯一属性写入虚入口，handler 内
**禁止直接调用 binding_->setX 写回 State**——增量路径（notify）与命令式路径
（setProp）都汇入此处，混入回写会造成无限递归。State 同步由两条既有通道负责：

- **命令式回声**：JS `setProp(id, prop, v)` → `View::setProperty`（非虚模板）
  转发成功后调基类 `echoBoundState(prop)`，按 parse 时记录的 typeHint 将
  `getProperty(prop)` 规范化值写回 State（SpinBox 的 clamp、Dropdown 的映射天然生效）。
- **用户交互**：onEvent 内显式调 `binding_->setX(bindKey_, …)`（在 notify 之外，安全）。

handler 需同时兼容两种值形态：原生 variant（bool/int64/double/Color，来自 notify）
与 string（来自 setProp 包装）。数值/布尔提取用 types.cppm 的
`typedToFloat` / `typedToBool`，一条分支兼容两链路。

### 最佳实践

- 放入 State 的字段只限于需要 `ref()` 绑定到 UI 的键。不需绑定的计数值、中间状态
  等用普通 JS 变量（`let count = 0`），避免无谓触发 rebuildTree。
- `state.update({...})` 批量更新时逐键尝试增量。建议确保所有 key 都有 ref 绑定，
  以走完整的增量路径（跳过 rebuildTree）。
- `resolveAllRefProps` 依赖 `JS_GetOwnPropertyNames(ctx, &tab, &len, props,
  JS_GPN_STRING_MASK | JS_GPN_ENUM_ONLY)` 中的 **STRING_MASK 必须与 ENUM_ONLY 组合**，
  否则 QuickJS 返回空属性列表导致 ref 标记不被解析。

### 与 PropBus 协作
- setProp 命中绑定属性时自动回声同步 State：
  setProp("userName", "value", "新值");
  → View::setProperty 转发赋值 → echoBoundState 按 typeHint 回写 form.name="新值"
  → trap → BindingRegistry::notify 兄弟视图增量更新（自身 handler 纯赋值幂等吸收，
  无递归；深度恒为一次回弹）。
- getProp / setProp 读写本身不触发重建，适合高频操作。

两通道互补：PropBus 的 getProp/setProp 命令式读写不触发 rebuildTree，State 属性写入则按绑定情况走增量或 rebuildTree，详见 [PropBus](3.%20PropBus.md)。

## 2.4 注意事项
- 1. 函数内不要缓存 State 值：const name = form.name 在 rebuild 时不会更新
- 2. Input/TextArea 不在每键敲击时同步 State（避免光标丢失），仅在 blur 和 setProp 时写入
- 3. ref() 仅在组件创建时生效，不支持运行时修改绑定
- 4. 双向绑定不阻止旧 onChange 回调
- 5. 对象式导出 export default View(...) 不受 State 影响
- 6. ref() 绑定覆盖全部组件类型的任意属性。state.key = val 查 BindingRegistry：
命中→增量；未命中→全量重建。state.update({...}) 同逻辑批量执行。
