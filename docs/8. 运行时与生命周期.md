# 运行时与生命周期

宿主 API（非组件），经 `kwikui` 模块导出：延时/周期调度、逐帧动画原语，
以及组件挂载/卸载生命周期钩子。

### 定时器：setTimeout / setInterval / clearTimeout / clearInterval

```js
import { setTimeout, setInterval, clearTimeout, clearInterval } from 'kwikui';

const id  = setTimeout(fn, ms);      // ms 后执行一次，返回取消用 id
const id2 = setInterval(fn, ms);     // 每 ms 重复执行，返回取消用 id
clearTimeout(id);                    // 两者共用同一 id 空间，clearInterval 为同名别名
```

行为：
- **帧驱动**：定时器在每帧 flush 时消费——`setTimeout(fn, 0)` 实际为
  下一帧（~16ms@60fps），短延时受帧粒度限制；interval 到期落在帧间隙会
  推迟到下一帧而非堆积连发（无浏览器式"追赶"，天然防雪崩）
- **自动清场**：HMR / 关窗时定时器随 JS 引擎销毁全部清空，无残留

### requestAnimationFrame — 逐帧动画原语

**核心语义：注册一个"下一帧执行一次"的回调——只执行一次，不会自动重复。**
（这是与 setInterval 最大的区别。）连续动画的标准写法是回调末尾再次注册
自己（自续循环），不再注册即自然终止：

```js
import { requestAnimationFrame, cancelAnimationFrame } from 'kwikui';

function step(ts) {                            // ts: 毫秒时间戳（本帧时刻）
    // ...本帧要做的事...
    if (未结束) requestAnimationFrame(step);   // 再注册 → 下一帧继续
}
const rafId = requestAnimationFrame(step);     // 只保证下一帧执行这一次
cancelAnimationFrame(rafId);                   // 取消尚未执行的那一次
```

要点：
- **ts 时间戳**：本帧的毫秒时刻（steady_clock）。用它对齐动画进度
  `p = (ts - startTs) / duration`——按真实经过时间插值，掉帧、高刷屏都
  不会忽快忽慢；不要用"帧计数 ÷ 帧率"推算进度
- **当帧生效**：回调在每帧 flush 后、微任务前执行；回调内改 State →
  当帧 rebuildTree → 当帧上屏，无中间态可见
- **帧节奏自持**：存在待触发 rAF 时主循环不休眠（保持帧调度）；全部
  停止注册后自动回落静止省电。注意对齐的是处理帧而非 vsync，非严格
  垂直同步节拍
- **自动清场**：HMR / 关窗时 rAF 队列随引擎销毁清空

为什么动画用 rAF 而不用 `setInterval(fn, 16)`：
- setInterval 帧中途随机执行——改动可能这帧白改或下帧才见；rAF 帧首
  执行、当帧生效
- setInterval 固定 16ms——掉帧时动画变慢、120Hz 屏一帧跑两次动画两倍
  速；rAF 用 ts 插值，帧率无关
- rAF 天然一帧一次、随帧调度；页面静止时框架可休眠，interval 不会停

与 C++ `animate`（见 [5. 动画系统](5.%20动画系统.md)）的分工：属性补间用声明式 `animate`
（引擎驱动，零每帧 JS 开销）；rAF 用于引擎覆盖不了的 **JS 逻辑逐帧驱动**
——自定义缓动、多属性联动、小游戏循环。

### 生命周期：onMount / onUnmount

所有组件可用的通用属性（无参回调）：

- **onMount**：树构建完成后对**新建节点**触发；reconcile 复用的节点不重
  触发；前序遍历父先于子——父回调内可安全访问子树。典型用途：挂载后
  初始加载（fetch 后填 State）、启动定时器/订阅 channel 主题
- **onUnmount**：节点被拆除时在**析构前**触发；后序遍历子先于父；
  HMR 整树重建不触发（JS 侧清理依赖引擎销毁自动回收）。典型用途：
  clearInterval / 退订 / 断开——**setInterval 的清理锚点**
- **配对纪律**：条件渲染子组件（数据面板/弹层内容）onMount 启动轮询、
  onUnmount 停止——只做一半就是泄漏（定时器继续跑 + 幽灵更新已销毁
  组件的 State）

### 示例：挂载启动轮询 + rAF 补间

```
import { View, Text, State, setTimeout, setInterval, clearInterval,
         requestAnimationFrame } from 'kwikui';

const state = new State({ count: 0, bar: 0 });
let pollId = 0;

View({
    onMount: () => {
        // 轮询：挂载启动；3s 后由 setTimeout 停（一次性清理的延时版）
        pollId = setInterval(() => { state.count++; }, 200);
        setTimeout(() => clearInterval(pollId), 3000);

        // 补间：rAF 自续 + 时间戳插值（首帧记起点，按真实耗时算进度）
        let startTs = 0;
        requestAnimationFrame(function step(ts) {
            if (!startTs) startTs = ts;
            const p = Math.min(1, (ts - startTs) / 500);
            state.bar = 300 * p;
            if (p < 1) requestAnimationFrame(step);
        });
    },
}, [
    Text({ text: '计数: ' + state.count, fontSize: 14 }),
]);
```
